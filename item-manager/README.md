# 物品管家（微信小程序）

管理家里的物品：按分组归类、拍照记录样子、记录每一件的使用起止时间；标记为“消耗品”的物品会预测什么时候用完，并提前发微信通知提醒补货。

基于**微信云开发**（云数据库 + 云存储 + 云函数），不需要自己的服务器。

## 功能

| 需求 | 实现 |
|---|---|
| 分组，显示分组下物品种类数量 | 首页分组卡片显示“N 种物品”；长按分组可重命名、删除（分组非空时不能删，可在物品编辑里换分组） |
| 照片上传 | 每个物品最多 9 张，上传到云存储；详情页轮播，点击可全屏预览；删除物品或移除照片时同步删除云端文件 |
| 物品是“类”，可派生多个“对象” | 物品下添加对象，每个对象有**开始使用日期**和**用完日期**：<br>没有开始日期 = 库存，有开始没结束 = 使用中，都有 = 已用完。<br>一次买了多个可以批量添加；列表上一键“开始用”“用完了” |
| 标签；消耗品预测用完时间、提前提醒 | 预设标签 + 自定义标签，分组页可按标签筛选。<br>带“消耗品”标签的物品显示预计用完日期；首页“即将用完”列出进入提醒期的物品；订阅后云函数每天 9 点检查并发送微信订阅消息 |

## 消耗预测怎么算

代码在 `miniprogram/utils/predict.js`，有完整测试。

1. **每个对象能用几天**：取最近 5 个已用完对象的使用天数，加权平均（越近权重越大，习惯变了能跟上）。还没有用完记录时，用物品上设置的“默认可用天数”。
2. **什么时候用完**：使用中的对象从开始日期加上可用天数；已经超期的视为今天用完。同时在用多个时以最晚的为准，然后每个库存再顺延一个周期。
3. **什么时候提醒**：用完日期前 N 天（物品上设置，默认 3 天）开始提醒；所有对象都用完、也没有库存时提醒“记得补货”。
4. 同一个用完日期只提醒一次；添加新对象、开始/结束使用后预测会变，进入新一轮提醒。

例：洗衣液上一瓶用了 30 天，现在这瓶 10 月 1 日开封，柜子里还有 1 瓶 → 预计 11 月 30 日用完，11 月 27 日开始提醒。

## 部署步骤

1. **注册小程序**并在[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)里导入 `item-manager/` 目录，把 `project.config.json` 里的 `appid` 换成你自己的。
2. **开通云开发**：开发者工具 → 云开发 → 开通，创建一个环境。如果有多个环境，把环境 ID 填进 `miniprogram/config.js` 的 `CLOUD_ENV`。
3. **建数据库集合**：云开发控制台 → 数据库，新建 `groups`、`items`、`instances` 三个集合，权限都选 **“仅创建者可读写”**。
   建议给 `instances.itemId`、`items.groupId` 建索引。
4. **配置订阅消息**（要提醒功能才需要）：
   - 公众平台 → 功能 → 订阅消息 → 公共模板库，选一个提醒类模板（如“物品到期提醒”“库存不足提醒”），记下模板 ID 和字段名。
   - 模板 ID 填到 `miniprogram/config.js` 的 `SUBSCRIBE_TEMPLATE_ID` 和 `cloudfunctions/remind/template.js` 的 `templateId`。
   - 按模板实际字段名修改 `template.js` 里的 `buildData`（默认是 `thing1` 物品名、`date2` 预计用完日期、`thing3` 提示语）。
5. **部署云函数**：右键 `cloudfunctions/remind` → “上传并部署：云端安装依赖”；再右键 → “上传触发器”，定时触发才会生效。
   可以在云开发控制台手动测试一次，返回 `{ checked, sent, failed }`。

## 关于提醒

- 小程序的订阅消息对个人/普通小程序只有**一次性订阅**：用户每点一次“订阅用完提醒”并同意，云函数才能发**一条**通知。发完后物品页会重新出现订阅按钮。
- 不订阅也能看到提醒：首页顶部“即将用完”会列出所有进入提醒期的消耗品。
- 定时触发器使用北京时间；预测里的“今天”也统一按北京时间计算。
